## 1. Anthropic Engineering: how agent memory works, and why "dreaming" fixes wrong notes
**Source:** https://www.anthropic.com/research/components-of-agent-memory
**Skill used:** ai-post-crafter
**Frame / angle:** Technique explainer / stakes-first: an agent that trusts its own wrong note is stuck, and the Mt. Moon Pokémon run shows the fix. Format: LinkedIn.

An AI agent playing Pokémon trusted a wrong note it had written to itself, walked off a one-way ledge, and looped three times. What got it unstuck was a step Anthropic calls "dreaming."

Anthropic's engineering team published a post on agent memory today (Nov 6). Memory here means notes an agent saves between sessions and reads back later. The failure it describes is quiet: the agent writes something wrong, then relies on it forever. In the Mt. Moon run, a bad note put the Pokémon Center on the wrong side of the mountain. Dreaming is an offline pass where the agent re-reads its old logs, like replaying the day, and checks its notes against what actually happened. After that fix, the agent reached Cerulean City at action 1,935. The runs with the uncorrected note and with no memory never got there.

Some numbers. On a database task called CL-Bench, memory raised Opus 5.5 from 0.655 to 0.838 mean reward. Sonnet 4.6, an older Claude model, barely moved (0.330 to 0.364), because it wrote theories into memory and never tested them. Prompting it to read memory and test its theories lifted it to 0.641. Telling a model what memory is for beat giving it fixed rules: a "record only failures" rule cut Opus 5's gain by 0.234.

Worth holding loosely: this is Anthropic studying its own models, much of it rests on specific benchmarks and single Pokémon runs, and the wiki results are mixed (wiki plus search scored 61% versus 53% for search alone, and on one other task the wiki gave no clear gain). The post itself says there is a lot left to learn.

My read, and it is speculative: for agents that learn on the job, storing more may matter less than auditing what was stored.

## 2. Guest essay on Anthropic's site: AI that builds scientific models should hand back the plausible alternatives, not one winner
**Source:** https://www.anthropic.com/research/teaching-ai-to-build-scientific-models
**Skill used:** ai-post-crafter
**Frame / angle:** Conceptual explainer / skeptical-leaning: a model that fits the data can still be wrong about why, so AI science tools should report what the data does and doesn't pin down. Format: LinkedIn.

A model that fits your data perfectly can still be wrong about why. A guest essay on Anthropic's site argues that AI tools which build scientific models should hand back the whole set of plausible explanations, not a single winner.

The authors are Jakob Macke, Daniel Gedon and Stefan Wahl (ELLIS Institute Tübingen, and AI for Science grantees). To be clear about what this is: a perspective piece, with no new experiments. Their anchor is the 1951 Hodgkin-Huxley model of the squid nerve. Its equations needed a variable raised to the fourth power, which suggested four moving parts. Decades later, structures of potassium channels showed four identical subunits. Huxley solved the equations by hand over three weeks.

The worry is what happens when AI agents do this loop automatically: write candidate model code, fit it to data, compare, revise. Many different settings can produce near-identical results, so one "best fit" hides alternatives. The authors want agents to return a weighted distribution of models. Their figure shows four clusters at 41%, 39%, 11% and 9%, which they present as illustrative, not as a measured result.

The sobering part is their own caveat. Systems like this have mostly rediscovered models scientists already knew, and evidence on problems with no known answer is thin. Interpreting a model, deciding what it means about the real system, is the step they say is hardest to automate.

My read, and I might be wrong: if AI-generated science gets cheap, the scarce thing becomes knowing what a result rules out. An answer that comes with its rejected alternatives is the version I would trust.
